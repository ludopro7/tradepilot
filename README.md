# TradePilot Local

Standalone/local-first TradePilot runtime. It does **not** require Supabase, Vercel, Render or a hosted database.

## Model
- Stocks: Zerodha Kite
- Crypto: Delta Exchange India
- New live entries are **manual only**: scanner -> review -> Execute -> broker.
- Local SQLite stores settings, execution claims and trade journal.
- Scanner never submits orders.

## Requirements
- Python 3.10+ (standard library only)
- Internet connection for market/broker APIs

## Run
Windows: double-click `start_windows.bat`.
macOS/Linux: `./start_mac_linux.sh`.
Then open `http://127.0.0.1:8787`.

## Credentials
Broker credentials are entered **only from the dashboard**. You do not need to create or edit an `.env` file for broker credentials. Open the app, use the Broker Connections section, enter the credentials, choose **Save locally**, and then use **Test connection**. Credentials are stored locally in SQLite and are never returned to the dashboard.

Zerodha now has a dashboard OAuth helper: save the Kite API key + API secret, then use **Login to Zerodha**. After the manual Zerodha login/2FA flow, TradePilot exchanges the returned request token for the access token and stores it locally. Zerodha requires the user login to remain manual; the request token is short-lived and the access token is valid for the trading day. The registered local redirect for this standalone build is `http://127.0.0.1:8787/`. The Delta API key and API secret are entered in the dashboard as well.

**Important for iPhone-only use:** this ZIP is a local Python application and requires a computer (or another device that can run Python) to host the server. `127.0.0.1` means the same device running TradePilot. Opening the dashboard on an iPhone does not make the Python server run on the iPhone, and a Zerodha redirect to `127.0.0.1` on the iPhone would point to the iPhone itself. For iPhone-only use, we need a separately hosted TradePilot backend with a public HTTPS redirect URL; do not expose the Kite API secret in a browser/mobile app.

## Safety
The execute endpoint requires an explicit `manualConfirmed: true`, and the UI requires a second browser confirmation. There is no scheduler that places live entries. Test with paper/test credentials or minimal size before live use.

## Manual execution model

Live entries are never generated by the scanner or any scheduler. The only live entry endpoint requires an explicit browser confirmation (`manualConfirmed=true`). If `TRADEPILOT_CONTROL_SECRET` is configured, it must also be supplied at final confirmation. Paper execution uses the same risk limits without contacting a broker.
